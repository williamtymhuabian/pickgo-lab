# PickGo Lab：轻量移动抓取仿真

## 打开

双击 `index.html`，用 Edge、Chrome 或其他现代浏览器打开。主文件内嵌全部运行代码，可以单独复制到其他电脑、断网使用；不需要 Python、Node、ROS、Docker、显卡驱动扩展或 npm 安装。

这是本机离线工具，不会访问外网、连接机器人或采集摄像头。浏览器自身的缓存和进程内存不计入本项目文件体积。单文件模式独立运行；需要与 MCP 共享控制时，请使用下面的本机服务。

## 网页与 MCP 共享控制

安装好 Python 3.10+ 和 Node.js 18+ 后运行 `python -B app.py`，打开 <http://127.0.0.1:8767/>。MCP 默认附接同一端口，共用服务端的唯一仿真进程，操作和状态互相可见。MCP 配置及使用方法见 [接入说明](mcp.md)。仅双击 HTML 的离线场景无法被 MCP 控制。

共享模式的时间在服务端推进，网页切到后台或关闭后任务仍继续；连接中断时网页禁用控制并显示提示，恢复后同步服务端状态。关闭 `app.py` 会结束该仿真进程。只关闭 MCP attach 客户端不会自动停止任务；需要停止时先调用 `stop_task`。

## 新增：原代码视觉验证

在项目根目录运行：

```powershell
python -B app.py
```

或双击 `start.cmd`，保持窗口打开。访问 `http://127.0.0.1:8767/vision.html`。该服务也提供原来的运动仿真首页，两页可以互相切换。Ctrl+C 停止服务。

视觉功能需要 `python -m pip install -r requirements.txt`；当前开发环境已有 OpenCV 4.11.0、NumPy 1.26.4，本次没有下载安装新依赖。已有 Python 与库的安装体积不计入项目文件体积。

可以调整合成方块的实际颜色、位置和旋转角，再选择要识别的颜色。检测框、中心、像素偏差和原始矩形角度来自你上传的 `legacy/utils.py` 中实际执行的 `det_color`、`det_rect`；使用原 `col_dict_daylight_shelf_1` HSV 配置。前端不提交真实中心、旋转角或物体世界坐标，服务端从 PNG 像素计算结果。原函数具有图像占比 4% 和轮廓尺寸门槛，小物体识别不到不一定是接入故障。

可以隐藏目标、选错颜色、关闭有效深度，验证失败状态；也可以选择本地 RGB 图片测试。图片在本机浏览器和回环服务之间传输，仅在内存中处理，不保存图片、不上传外网。上传 RGB 图片时没有配对深度，不会补造距离。

`legacy_vision.py` 使用 AST 只选取原函数定义及 HSV 配置，不导入整个 `legacy/utils.py`，因此不触发 ROS、主服务、串口夹爪或机械臂初始化。原函数体和其中的 0.4 秒等待保留；仅在适配环境中将旧 NumPy 别名 `np.int0` 映射到等价的 `np.intp`。原文件未修改，页面显示原文件 SHA256 和函数行号，测试还会与 legacy/source-manifest.json 比较。

深度处理为新适配器：对检测中心 5×5 区域的非零深度取中值，全部无效或没有深度帧时明确返回空值。没有直接复用原主服务的深度回调。

**本阶段是独立的相机输入/识别验证。合成图是可控的二维 RGB-D 标定测试图，尚非三维场景的真实成像投影；原自动搬运仍使用简化几何位置，没有把本页检测结果作为机械臂控制输入。下一阶段才接相机内外参、坐标转换与视觉对中闭环。**

直接双击 `vision.html` 或从旧的纯静态服务打开时，可以预览测试图；页面会明确提示识别服务未连接，不会用 JavaScript 假造原 Python 检测结果。

## 操作

1. 选择红色、蓝色或黄色方块，点击“开始搬运”。
2. 可选 1×、3×、6× 播放；暂停后点击“继续”。“停止任务”保留当前位姿和物体状态，“重置场景”恢复初始场景。
3. 拖动画面旋转视角，滚轮缩放；三维/俯视/侧视切换，“跟随”放大观察机器人。
4. 展开“手动调试”，可拖动四个关节和夹爪开口。先点击“收回运输位”，再按住前进/后退/左转/右转；方向键或 WASD 在面板展开且不编辑输入时也可使用。自动任务中锁定手动操作。
5. “导出状态 JSON”保存仿真位姿、目标状态和事件记录。

自动流程：前往取物台 → 停稳 → 虚拟感知 → 抓取、抬升 → 放入车载托盘 → 收臂 → 绕障运输 → 从托盘重新抓取 → 投放 → 收臂核验。

## 已实现的仿真

- 三维几何渲染：普通浏览器 Canvas 2D 投影与面排序，程序生成全部模型，不下载模型、纹理、字体或第三方库。
- 差速底盘运动学与左右轮角速度、路径跟踪、A* 栅格寻路、路径平滑、带间隙的圆形底盘与矩形障碍碰撞检测。
- 四轴机械臂：底座回转、肩、肘、腕；双连杆解析逆解、正运动学、关节限位、平滑关节插值、平行夹爪开合。
- 抓取只在夹爪与目标位置吻合时成立；目标随后跟随夹爪或托盘。运输前验证收臂与物体固定。
- 可取消、暂停、继续的显式任务状态机，以及任务后置条件核验。
- 离线模式前后台切换不补跳时间；共享模式在服务端持续推进。静止时不重复重绘，画面约 30 帧/秒，设备像素比上限为 2。

这是通用小机器人运动学原型，不是原法奥机械臂、Woosh 底盘的精确数字孪生。模型采用约 0.43 × 0.34 m 底盘，上臂 0.28 m、前臂 0.25 m、工具 0.09 m；这些是此演示场景的几何参数，不是实物采购建议或负载承诺。

## 仿真边界

“虚拟感知”直接读取场景目标的已知几何位置，没有运行真实 RGB-D 视觉算法。物体夹持与托盘固定使用几何约束，不计算力、摩擦、质量、重心或惯性。只有底盘具备本示例的简化碰撞检测，没有完整的机械臂自碰撞、环境碰撞或连续扫掠检测。因此可验证任务流程和几何可达性，不能据此判定实物抓取可靠性、避碰安全或抗倾覆性能。

手动调试用于观察运动学；“收回运输位”直接设置仿真关节角，手动夹爪开合不触发物体抓取。自动任务中的收臂使用平滑插值。停止仅表示本地数值积分停止，不是实物急停的实现。

## 文件与开发

- `index.html`：完整的离线应用，内嵌核心、渲染器和界面；可单独携带。
- `simulator-core.js`：独立、无界面的仿真核心源文件，供测试及后续接入任务接口。
- `tests/simulation.test.cjs`：使用 Node 内置断言的测试，无 npm 依赖。
- `vision.html`：相机与识别验证界面，内嵌图像/深度帧适配器和输入控制。
- `legacy_vision.py`：原函数加载、HSV profile 选择、结果规范化与有效深度过滤。
- `app.py`：仅绑定 127.0.0.1 的本地服务；提供共享状态、动作、识别和两个页面。
- `Constants.py`、`utils.py`、`robot.py`：字典配置、业务动作和仿真通信函数。
- `mcp_server.py`：stdio 工具入口，默认连接同一网页服务；`--standalone` 可使用独立场景。
- `start.cmd`：Windows 启动入口。
- `tests/test_vision.py`：原代码、图像、深度和本地 HTTP 接口测试。

有 Node 时可运行：

```powershell
node tests/simulation.test.cjs
python -B tests/test_vision.py
python -B tests/test_mcp.py
```

修改 `simulator-core.js` 后，需要把 `index.html` 中 `<script id="sim-core">` 到对应 `</script>` 之间的内容同步为该文件内容；测试会检查两者一致性。修改界面、渲染器则直接编辑 `index.html`。

运动学、场景障碍、物体初始状态和任务步骤集中在核心中。`RobotSim.Simulation` 提供 `start(id)`、`tick(dt)`、`pause()`、`resume()`、`cancel()`、`reset()`、`snapshot()`。Python、HTTP、MCP 接口已经接入这一核心；未来可在 `robot.py` 增加硬件后端，并补齐实体设备的限位、标定、急停和动作回执。当前只实现 sim，传入其他 backend 会报错，运行原项目的 `/grab` 请求不会控制此页面。

测试覆盖三种物体的完整搬运、正逆解精度、不可达目标、A* 路径间隙、暂停继续、取消持物状态、重置及底盘手动互锁。它们验证本示例模型的行为，不是对真实设备的验收。
